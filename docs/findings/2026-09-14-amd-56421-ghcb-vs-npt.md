## APM law → wininit `0x50006`

33047 §2.21.7 (APM §15.25 same combine):

- Nested tables map **GPA → HPA** (`hCR3` / VMCB `nCR3`). Guest CR3 still
  maps GVA → GPA.
- A page is **executable** only if it is executable at **both** guest and
  nested/host levels. Same for writable.
- Nested walk of guest page tables is a **user write** at the host level
  unless ROGPT. Identity PTEs keep **U/S=1 R/W=1**.
- `#VMEXIT(NPF)` `EXITINFO2` = **faulting GPA**. `EXITINFO1.ID` = nested
  **code fetch**.

Identity NPT: **GPA = HPA**. `npte::trap_execute()` sets NX on that GPA.
Every guest whose page tables map that PFN takes NPF on fetch — **before**
any CR3 filter in the NPF handler. Windows **ntdll / user32 / kernel32
`.text` is a shared PFN**. Relic CR3 vs csrss CR3 does not isolate nested
NX. That is the Cycle 9 hang (Appinfo / UAC / wininit `0x50006`), not an
Intel EPT execute-only recipe.

GMET (VMCB `090h` bit 3, Table 15-21): NX=0 + U/S=1 + GMET = **supervisor
fetch NPF**. Identity must **not** set GMET. User-execute trap = **NX=1**,
keep U/S=1 so data reads (hasher) do not NPF.

Relic `.text` GPAs are **private** PFNs. Identity NX there does not share
with csrss. OS DLLs must never get `trap_execute` / hide / ZPPI.
