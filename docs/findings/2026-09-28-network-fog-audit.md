## Почему отсутствие прав хоста не спасает

Симуляционный туман входит в проверяемое состояние мира. Участник может
испортить свою локальную копию мира прямой записью; хост не переписывает её
каждый кадр. Запись в обе локальные копии мира тоже не рассылает изменение
остальным компьютерам. Поэтому проверка «я не хост» не делает такую запись
допустимой. Нужен запрет изменения симуляционного тумана во всех сетевых матчах.

`World_IsMultiplayerGame` в исследованной сборке 16.3.11308 читает
`GameSetup` type=1; C++ Map knowledge читает то же поле напрямую. Подробности
проверяемых поверхностей: [CHECKSUM_AUDIT.md](../CHECKSUM_AUDIT.md).

## Найденные дефекты и исправления

1. **Map knowledge / Everything.** Первоначально неизвестный состав лобби
   (`-1`) принимался за отсутствие других людей; значение по умолчанию было
   Everything. Это исправлено ранее: default Off, неизвестный состав блокирует
   запись, сетевой тип игры блокирует запись независимо от состава лобби.
2. **Reveal Map (Memory).** Реальная `BuildFowDebugGuardPrelude` вопреки своему
   комментарию возвращала `true, false, 'live'` для любого обычного матча.
   После этого OneShot мог вызвать исходный `FOW_PlayerExploreAll`, а Hide —
   `FOW_UnExploreAll`/`FOW_PlayerUnExploreAll`. Восстановлена проверка
   `World_IsMultiplayerGame`: разрешено только достоверное `false`; отсутствие
   функции, ошибка или неожиданный тип ответа блокируют симуляционные вызовы.
   В повторе остаются только изменения отображения.
3. **Переход между матчами.** Очистка прежнего Map knowledge могла записать
   ноль в новый сетевой мир при повторном использовании относительного адреса
   тумана. Теперь сетевой или неизвестный тип игры сбрасывает локальное
   состояние владения и выходит без записи, включая выключение и выгрузку.
4. **Расположение настройки.** Map knowledge перенесён в Camera сразу под
   Reveal Map. Настройка видна и до матча; default остаётся Only what it scouted.

Пункт 2 подтверждён исполнением фактических Lua-фрагментов приложения в
Lua 5.3: до исправления тесты получили 1 запись Explore и 2 записи UnExplore
в сетевом/неизвестном режиме; после — 0. Пункт 3 воспроизведён тестом,
который связан с настоящим `ai_map_sight.cpp`, а не копией условия.

## Что проверено дополнительно и чего данные не доказывают

- В журнале второго матча AI takeover и установка оценок производства были
  до SyncError, поэтому по времени исключить их целиком нельзя.
- `eco_ai_cuts` (21:36:09.342) и загрузка `hybrid_1.scar` (21:36:09.594)
  идут после уже зарегистрированного расхождения (21:36:09.136). Эти конкретные
  поздние вызовы не объясняют начало данного рассинхрона.
- Запись sim fog в 21:36:07.926 — прямое подтверждение недопустимой операции
  перед расхождением. Это сильнейшая найденная причина первых двух случаев.
- Дефект Reveal Map подтверждён в коде, но вызова кнопки перед теми двумя
  SyncError в сохранённом журнале нет. Это дополнительный исправленный риск,
  а не доказанная вторая причина тех же вылетов.
- Сетевые ошибки сокетов в `unhandled` сами по себе не объясняют разные CRC.
  «Application crashed» после разрыва не доказывает отдельный исходный AV.
- В текущем журнале 28 сентября есть отказ Map knowledge из-за неизвестного
  состава игроков. Это подтверждает работу этой ветки защиты; не заменяет
  проверку нового матча с друзьями.

Контрольные суммы, сетевые проверки и механизм обнаружения рассинхрона не
изменялись. Исправления устраняют выявленные локальные изменения симуляции.
Сетевой матч после этих изменений не запускался; обещать отсутствие всех
возможных рассинхронов по стендовым тестам нельзя.
