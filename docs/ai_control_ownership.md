# Relic AI control ownership

This map prevents two systems from writing the same Relic AI control in an
armed AI BOT session. It is based on source review and host tests; it is not a
claim that every native has been measured in a live match.

## Active ownership

| Layer and control slice | Active owner while `AOE4HOOK_ECO_CPP=true` | Alternative owner when C++ AI BOT is off | Enforcement |
|---|---|---|---|
| A: `ScoringFunctions_*` replacements and `GetDesiredTCCount` | Session installer in `ai_session.cpp` plus `__EcoAct` installed by `ai_runtime.cpp` | A selected standalone scoring package such as `eco_upgrades.lua` or `warmonger.lua` | Hybrid does not install/reassert scoring while the flag is set. |
| A: unit-family availability cuts | `ai_runtime.cpp`, from the published C++ plan | Hybrid tier restriction only when C++ AI BOT is off | Hybrid skips its cut and queue paths under `cppOwnsCuts` / `cppOwnsQueue`. Catalog per-PBG cuts are disabled after Relic fatal assert `0x5961C7`. |
| B: income desires | `__EcoAct_ApplyDesire` generated by `ai_runtime.cpp` | Explicit Fine-tune application or Hybrid economy loop | Hybrid exits its economy write path; standalone eco package does not run its Layer B bootstrap. |
| B: gatherer override | `__EcoAct_ApplyDesire` | Explicit Fine-tune application | The C++ actuator records a successful value before suppressing a repeat. |
| B: strategic intentions | `__EcoAct_ApplyDesire` | Explicit Fine-tune application or Hybrid posture | `cppOwnsIntent` gates both Hybrid variants; `eco_upgrades.lua` now has the same guard. |
| B: target `PushScore` multipliers | `__EcoAct_ApplyDesire` | Explicit Fine-tune application | One value cache per target key in `__EcoAct.prev`. |
| C: personality bag | `ScarApplyAiTune` only after an explicit profile/package action | The same explicit action | Runtime and Hybrid do not set personality. A new personality is fixed until another explicit action. |

The initial intention writes in the session scoring installer are bootstrap
writes by the same C++ AI BOT owner. The runtime then publishes the complete
Layer B state through `__EcoAct_Apply`; they are not a second periodic
controller.

## Commit contract

The worker computes a pure plan, then `AiRuntimeOnPlanPublished` creates a
generation. The window-thread actuator receives that generation through
`WM_SCAR_AI_COMMIT`. `__EcoAct` stores the generation only after all required
natives and availability writes succeed. C++ keeps the update dirty until the
matching generation is acknowledged, so an old posted script cannot clear a
new plan.

Disarming or rearming increments the runtime session epoch. A plan computed
for an earlier epoch is discarded before it can mutate actuator state. This
keeps a prior match or disabled session from applying a late policy.

## Ownership release

The flag `AOE4HOOK_ECO_CPP` means "the C++ AI BOT owns Layer A/B right now".
`eco_ai_on` sets it and parks the Files/hybrid `__EcoContest_Tick` behind a
marked stub (`__EcoContest_TickPrev`). `kHandover` sets the flag back to
`false` and restores the parked tick (`cppOwnsFlagRelease`, installer v50).
`__EcoAct_Restore` pops the four target-score multiplier ids the actuator
pushed. Without the release, every hybrid `cppOwns*` guard and the
`eco_upgrades.lua` contest stayed disabled after AI BOT off with no owner.

Slices that cannot be restored (no getter / clear native): income desire,
strategic intentions, gatherer override. They keep the last C++ value until
another explicit owner writes them. Personality is never touched by the
runtime, so nothing to restore.

## Layer C / difficulty → Layer B dependency

`AI_SetPersonality`, `AI_RestoreDefaultPersonalitySettings`, economy
overrides and `AI_SetDifficulty` reload the personality bag on the AI thread.
Whether that reload resets income desire / intentions / target multipliers is
**unmeasured** (IDA session did not open). The runtime does not depend on the
answer: every explicit action of that kind calls `__EcoAct_LayerBInvalidate()`
(installer v55: forgets the applied Layer B keys of `__EcoAct.prev`, keeps
family cuts; per-PBG locks are disabled) and then `AiRuntimeInvalidateLayerB()` (bumps a
generation while armed). The next lean commit rewrites the slices C++ still
owns with unchanged values. Idempotent natives, one extra `ScarDoString` per
explicit user action, never per tick.

Writers wired: `AiSessionApplyDifficulty` (`eco_ai_diff` enable script
carries the Lua), `ScarApplyAiTune` when `personalityMode != 0 || econMode != 0`
(Fine-tune / AI Profiles apply). Fine-tune slices the user owns
(`ai_apply_*` on) are excluded from the C++ send mask as before.

## Best-effort slices

Relic has no `expansion` production intention and civ-specific income ids
(`RT_Merc_Byz`, `RT_Militia_HRE`, `RT_Popcap`) may not exist for the local
civ. `__EcoAct_ApplyDesire` writes them with `required=false`: a rejected
write is logged in `prev` as absent and does not hold `gen` open. Base
resources, gatherer override, the ten Relic intention strings and the four
target multipliers stay required (a miss keeps `gen` unconsumed so the same
generation is retried once).

Lua-mock evidence: `tests/adversarial/test_ai_handover.py` runs the real
embedded enable / handover / installer scripts under lupa.

## Excluded writers

Both `sdk/scar/hybrid_core.scar` and the deployed `hybrid_c.scar` recognize
the C++ ownership flag. Their guards cover intentions, production cuts, queue
scans, placement scans, the alternate economy loop, and the alternate nearby
resource contest. `eco_upgrades.lua` also skips its bootstrap intention write
when the flag is active.

Standalone scoring packages are mutually exclusive with the armed C++ AI BOT
mode. Loading one before the C++ session is allowed; the next C++ actuator
commit becomes the owner of its Layer B values.

## Evidence and remaining live checks

Host tests verify generation-side math, the static ownership guards, and the
absence of hard-coded TC limits. `tests/adversarial/test_ai_production_math.cpp`
checks the Hybrid and eco-package guards; `test_eco_idle.py` checks that the
villager contest does not interrupt a working squad.

An offline/skirmish run still needs to record native-call success and the
`__EcoAct.gen` progression across: first enable, fast-age, mass-army,
disable/re-enable, and a deliberate native failure. No personality retuning
should be added before that evidence shows a persistent Layer C mismatch.
