## Ловушки сборки и прогона (2026-09-08)

Каждая стоила отдельного цикла.

1. **Инжектить только из `internal\x64\Release\`.** Рядом лежит устаревшая
   `internal\x64\InternalInjector.dll`; сеанс на ней выглядит нормально и не
   доказывает ничего. Опознаётся по логу: печатается строка, которой в
   исходниках уже нет, и нет ни одной строки `AVUI tree`.
2. **`run_host.ps1` запускать голым вызовом.** Каталог `vswhere.exe`
   (`Microsoft Visual Studio\Installer`) должен быть в `PATH` — вложенные
   `.cmd` зовут его без пути. И **не перенаправлять вывод** (`2>&1`, `*>&1`):
   в раннере `ErrorActionPreference = Stop`, а stderr нативной программы в
   конвейере PowerShell 5.1 становится `NativeCommandError`, и набор умирает
   на первом питоновском тесте. Строки вида «empty json fails» — это названия
   проходящих тестов; смотреть `[OK] adversarial host tests`.
3. **Не давать MSBuild `-m` с общим `IntDir`** — несколько CL.EXE пишут в один
   `vc143.pdb` и валятся с `error C1041`, а решение возвращает **0** от
   последнего проекта. Проверять не код возврата, а время и размер DLL.

Лимит строкового литерала MSVC — 16380 байт. Встроенный Lua нарезан на куски
именно поэтому. Оба скрипта скоринга (инъекция сессии и установщик
актуатора) собирает одна функция `AiScoringScriptAppend`
(`ai_scoring_script.h`) по одному упорядоченному списку слоёв; там же ядро
актуатора `kAiEcoActCoreLua`, `kAiEcoActRestoreLua` и версия
`kAiEcoActInstallerVersion`. Тела скоринга Relic, общие для обоих, — в
`ai_eco_act_lua.h`. Точный результат лежит в `tests/adversarial/golden/`
(`test_ai_scoring_script.cpp` сверяет байты; после правки Lua —
`test_ai_scoring_script --write`), Lua-тесты исполняют именно его. Переполнил —
`error C2026`, режь по границе секции на соседние `R"STK(...)STK"`
(`test_raw_literal_limit.py` проверяет каждый литерал).
