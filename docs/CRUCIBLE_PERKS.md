# Очки талантов Crucible

Оверлей: **Офлайн → Scar / Lua / Desync → Crucible**.
Редактор работает на экране талантов в меню Crucible; активный матч и SCAR VM не нужны.

1. Откройте таланты Crucible в игре.
2. Введите точное число свободных очков в поле «Текущие очки».
3. Нажмите «Проверить без записи» для поиска или «Установить 114514 очков» для поиска и записи.
4. При неоднозначном результате купите или верните талант, введите новое число и повторите поиск: сохранённые кандидаты фильтруются по новому значению.
5. После записи купите или верните талант и выйдите из Crucible в главное меню, чтобы игра сохранила изменение.

«Отменить изменение очков» восстанавливает предыдущее значение, только если очки всё ещё равны записанным 114514 и тег ячейки не изменился. Отмена доступна в текущем запуске игры. «Сбросить поиск очков» сбрасывает кандидатов, сохраняя возможность отмены.

## Реализация и источник

Сравнение выполнено с [aoe4_perk_editor.py, Kindred0014](https://github.com/Kindred0014/aoe4-crucible-perk-editor/blob/main/aoe4_perk_editor.py) 2026-09-16. До изменения вкладка содержала только Spawn / Combat / World; редактора Crucible не было.

Самостоятельная C++ реализация использует описанную в исходнике эвристику: 16-байтное выравнивание, старший байт соседнего qword не меньше `0x80`, чистые соседние числа в диапазоне `[-1000, 100000000)`, выбор единственного лидера по шести соседям. Сначала проверяется int64, затем int32. Это эвристика исходного инструмента, а не подтверждённый ABI текущей версии игры. При равенстве оценок запись не выполняется.

Файлы: `crucible_perks.cpp`, `crucible_perks_search.h`, `ui_crucible_perks.cpp`. Фоновый поток читает приватную неисполняемую writable-память порциями по 1 МиБ. Буфер снимка и стек сканирующего потока исключены: иначе внутренний сканер мог бы обнаружить собственные копии искомых данных. Хранятся только кандидаты с подходящим тегом, максимум 65536 на разрядность. При превышении лимита частичный результат отбрасывается.

Перед записью заново проверяются область, значение и тег. Compare/exchange не перезаписывает число, изменённое игрой после поиска. После записи выполняется чтение для проверки. Защита страниц не меняется; код и image-секции не записываются. Во время поиска DLL удерживается ссылкой, освобождаемой через `FreeLibraryAndExitThread`; ожидания потока из DllMain нет.

Отличия от Python: адреса и отмена хранятся только в текущем процессе, JSON с адресами между перезапусками не используется; исполняемая память исключена. Добавлены отмена поиска, сброс и русские подписи. Проверка без записи также сохраняет кандидатов для уточнения.

## Проверка

`tests/adversarial/build_crucible_perks.cmd` проверяет неоднозначные результаты, ранжирование, уточнение по изменённым очкам, теги, int32/int64, границы порций, лимит кандидатов, dry-run, запись и отмену, изменённые значения, readonly/executable/freed память и полный поиск в памяти тестового процесса.

Проверки 2026-09-16: целевой тест прошёл, баланс ImGui обоих изменённых экранов и наличие всех русских переводов проверены. Сборки `Release|x64` прошли для `internal/x64/Release/InternalInjector.dll` и `dist/AOE4HOOK.exe`; новая DLL включена в standalone-пакет.

Дополнительный общий `run_quality_suite.py` из навыка ImGui прошёл структурные и семантические проверки (30/30), но его компиляция шаблонов недоступна: скрипт требует `g++`/`c++`, которых нет в PATH. Сами изменённые исходники собраны штатным MSVC проекта.

В живой игре поиск, обновление интерфейса и сохранение прогресса ещё не проверены: RelicCardinal во время работы не был запущен.
